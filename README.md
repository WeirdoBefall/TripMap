# TripMap 中文智能旅行规划助手

支持用中文、英文或混合语言描述需求，生成包含航班状态、酒店建议、每日行程和预算估算的中文旅行方案。

## 启动

使用 Python 3.12，在项目目录运行：

```powershell
pip install -r requirements.txt
python app.py
```

访问 `http://127.0.0.1:8000`。项目使用 PostgreSQL 保存会话，启动时需要数据库可连接。

在本地 `.env` 中配置以下变量，请勿提交真实密钥：

```dotenv
GOOGLE_API_KEY=你的大模型密钥
AVIATIONSTACK_API_KEY=你的航班接口密钥
TAVILY_API_KEY=你的搜索接口密钥
DATABASE_URL=postgresql://用户名:密码@主机:端口/数据库名
# 可选：仅在未说明出发地时使用；不设置则查询所有出发地
# DEFAULT_ORIGIN_IATA=PEK
```

大模型使用 `gemini-3.5-flash-lite`，也兼容通过 `GEMINI_API_KEY` 配置密钥。

## 航班识别与查询规则

- 大模型通过结构化 JSON 识别出发地、到达地以及国家、城市或指定机场，替代英文正则匹配。
- 只说国家：默认使用首都的一个主要机场。例如中国 → PEK、美国 → IAD、澳大利亚 → CBR、加拿大 → YOW、阿联酋 → AUH。常见国家使用本地首都机场表，其他国家使用模型提取并经机场库校验的首都机场；无法确认时提示补充。
- 说到城市：使用模型列出的都市圈机场，并从 `airportsdata` 补全同国家、同城市的全部机场代码。例如上海 → PVG/SHA，东京 → HND/NRT；纽约还可覆盖 EWR。机场覆盖范围取决于机场库和模型识别结果。
- 明确指定机场：只查询指定机场，不扩展到全城。城市代号如 TYO 会由模型展开为实际机场代号。
- 每个出发机场与到达机场的组合分别调用 AviationStack `/v1/flights`，最多六路并发，合并去重后最多显示十条；不会因为已达到显示数量就跳过其他机场组合。多机场会增加接口调用次数。
- 仅指定目的地时不再默认从达卡出发；可通过 `DEFAULT_ORIGIN_IATA` 自行设置默认出发机场。
- 仅在用户明确要求全球航班时查询全球数据。地点缺失、歧义、模型失败或无效机场代号会提示补充或重试；部分接口请求失败时保留成功结果并提示不完整。

此接口查询的是实时航班状态，不提供机票报价，也不代表未来出行日期的可预订机票。空结果不代表没有该航线。接口权限和调用额度以 AviationStack 账户套餐为准。

## 验证

以下测试使用真实机场库，模拟模型及航班 API，不消耗外部接口额度，也不连接数据库：

```powershell
python -m unittest discover -s tests -v
```

`python test.py` 会连接真实外部服务和数据库，运行完整旅行规划流程。
